# Milestone 07 — Make HOL4 the Independent Build-Time Replay Authority

## Objective

Replace Candle as the primary build-time proof authority with the pinned HOL4 kernel, WITHOUT introducing a new hand-written PCUIC→HOL4 theorem port.

The intended architecture is:

```text
MetaRocq source + all retained PCUIC proof/specification data
                |
                | self-reflection / replay program
                v
LambdaBox
                |
                | proved Peregrine→CakeML path
                v
CakeML selfhost/replay program
                |
                | evaluated/compiled inside HOL4
                v
HOL4 theorem objects that certify:
  1. the complete replay computation accepted every in-scope proof;
  2. the exact executable state used that exact proof corpus;
  3. the exact downstream program is the one later compiled to machine code.
```

Do NOT create a parallel hand-maintained MetaRocq metatheory in HOL4.

The entire self-reflective replay/compilation process is the proof-producing bridge.

## 1. Keep HOL4 pinned

Reuse the existing repository pin:

```text
HOL4 commit:
40dd5b03de658f4bd9e3f4225fb0f1602ac90467
```

Use only:

```text
.aegis/hol4/bin/hol
.aegis/hol4/bin/Holmake
```

for final evidence.

Verify before every publication run:

```bash
test "$(git -C .aegis/hol4 rev-parse HEAD)" = \
  "40dd5b03de658f4bd9e3f4225fb0f1602ac90467"

git -C .aegis/hol4 diff --exit-code
```

If the HOL4 pin changes, invalidate and rebuild every theorem downstream of the change.

## 2. Create one HOL4 selfhost theory directory

Create:

```text
formal/hol4/selfhost/
  Holmakefile
  MetaRocqReplayScript.sml
  MetaRocqCakeMLScript.sml
  MetaRocqMachineScript.sml
  MetaRocqE2EScript.sml
```

Do not scatter the final proof graph across ad-hoc temporary scripts.

The directory MUST depend on the exact pinned CakeML HOL theories used by the compiler proof.

## 3. Import data, not trust

Treat all MetaRocq/Rocq-generated material as untrusted input data:

```text
source snapshot
certificate corpus
assumption ledger
LambdaBox artifact
CakeML artifact
digest manifests
```

HOL4 must not infer “valid proof” merely because:

- a Rocq `.vo` exists;
- a MetaRocq command returned success;
- a JSON field says `accepted: true`;
- a hash matches a file.

The HOL4 theory must reconstruct/check the complete replay result from the exact data and the exact verified replay semantics.

## 4. Model the replay result as a theorem-producing computation

The desired HOL4 object is conceptually:

```text
|- replay_complete_source exact_source_state = Accepted exact_replay_report
```

and, from the correctness/refinement theorem of the replay program:

```text
|- replay_complete_source exact_source_state = Accepted report
   ==> AllInScopeProofsValid exact_source_state
```

The concrete build should then derive:

```text
|- AllInScopeProofsValid exact_source_state
```

This is the point at which the ordinary Rocq kernel ceases to be an authority for the final claim.

The proof-producing computation MAY internally mirror MetaRocq/PCUIC proof replay; the final acceptance theorem MUST be a HOL4 `thm`.

## 5. Do not hand-write one HOL4 proof per MetaRocq theorem

The project goal is NOT:

```text
manual HOL theorem #1
manual HOL theorem #2
...
manual HOL theorem #N
```

Instead, use the same generic reflected replay mechanism over the complete concrete certificate corpus.

The complete theorem set may still be exposed individually for auditability, but they should be generated by one uniform replay/evaluation pipeline.

The required completeness theorem from Milestone 03 ensures that “all replayed proofs” equals “all in-scope source proofs”.

## 6. Require proof-producing evaluation, not oracle injection

Never use:

```sml
mk_oracle_thm
```

or any equivalent unchecked oracle to create final acceptance results.

For generated HOL4 theorems inspect:

```sml
Thm.hyp th
Tag.dest_tag (Thm.tag th)
```

The final policy SHOULD reject:

- unexpected hypotheses;
- unexpected oracle tags;
- arbitrary imported axioms outside the explicit assumption policy.

A small inspection helper can be:

```sml
fun require_clean expected th =
  let
    val (oracles, axioms) = Tag.dest_tag (Thm.tag th)
  in
    if not (aconv (Thm.concl th) expected) then
      raise Fail "unexpected theorem conclusion"
    else if not (null (Thm.hyp th)) then
      raise Fail "unexpected hypotheses"
    else if not (null oracles) then
      raise Fail "unexpected oracle tags"
    else
      th
  end
```

Adjust the exact accepted tag/axiom policy to the pinned HOL4 kernel and explicitly documented foundational assumptions. Do not simply discard tags.

## 7. Make proof-corpus completeness a premise of the replay theorem

The HOL4 build must know that the replay input is complete.

Bind these exact inputs:

```text
source snapshot digest
quoted environment digest
certificate corpus digest
assumption ledger digest
replay-program digest
```

The final replay theorem must depend on a mechanically checked completeness fact, not only on an external count.

If the source has N proof-bearing declarations, dropping one entry must make HOL4 unable to derive the final “all proofs valid” theorem.

## 8. Preserve all source assumptions in the theorem dependency graph

Import the assumption ledger as explicit premises/dependencies.

The result may initially have the shape:

```text
|- AllowedPCUICAssumptions assumptions
   ==> AllInScopeProofsValid exact_source_state
```

That is acceptable during development.

It is NOT acceptable to publish it as unconditional validity if the premise is still undischarged.

Generate:

```text
generated/hol4-selfhost/assumptions.txt
generated/hol4-selfhost/theorem-tags.txt
generated/hol4-selfhost/replay-theorem.txt
```

for human audit.

## 9. Build the replay theory locally

Use the pinned HOL4 build:

```bash
export HOLDIR="$PWD/.aegis/hol4"
export PATH="$HOLDIR/bin:$PATH"

cd formal/hol4/selfhost
Holmake
cd ../../..
```

If CakeML theories are outside HOL4's standard path, add only the exact pinned CakeML theory directory required by the build through `Holmakefile` includes.

Do not point at a mutable global CakeML checkout.

## 10. Save theorem identity separately from theorem meaning

Record:

```text
HOL4 source commit
CakeML source commit
selfhost theory source digests
replay theorem name
theorem conclusion
theorem dependency/assumption summary
exact certificate-corpus digest
```

A theorem-name string by itself is not evidence. The HOL4 theory files and their exact dependencies must be reproducible.

## 11. Add deliberate rejection tests

All of the following MUST prevent the final replay theorem from being produced:

- delete one certificate;
- change one theorem statement;
- change one proof/body AST;
- change the source snapshot;
- add one unexpected assumption;
- insert an oracle theorem;
- substitute a stale replay report;
- run against a different HOL4 commit.

## Completion gate

Milestone 07 is complete only when:

- HOL4 builds from the pinned commit;
- the exact complete replay state is consumed by HOL4;
- HOL4 derives a real theorem for successful complete replay;
- the theorem is tied to the exact certificate/source state;
- unexpected assumptions/oracles fail closed;
- no hand-written theorem-by-theorem MetaRocq port is required;
- ordinary Rocq acceptance is no longer sufficient to authorize the final proof-validity claim.
